# Yandere Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a playable five-day Godot 4 stealth demo. The player follows a scripted-in-Blender anime target through a living school: attending class, taking photos, collecting her items and managing three meters. The week ends in one of four endings.

**Architecture:** The game logic is pure `RefCounted` models with `class_name`, unit-tested headless:
- the clock, the scheduler, the meters, photo scoring, attendance, the week progress and save, and ending resolution.

Thin autoload Nodes wrap those models and emit typed signals. Scenes (player, target, teacher, students, school) consume the signals.

All 3D assets are generated by Python scripts in `yandere_demo/blender/`. They run headless via the Blender CLI so the build is reproducible, and are iterated visually through blender-mcp. They export `.glb` into `assets/models/`. Godot post-import scripts swap the materials to toon shading.

**Tech Stack:**
- Godot 4.7.2 (`/opt/homebrew/bin/godot`), GDScript
- Blender 5.2.2 (`/Applications/Blender.app/Contents/MacOS/Blender`, plus blender-mcp)
- Python 3 stdlib for audio synthesis
- godot-mcp for scene inspection and runs

Phase D (Task 23a–23d) also follows the addendum `docs/superpowers/specs/2026-10-26-astolfo-target-design.md`. Section references (§) below point into it. ## Global Constraints

**Locations and git**
- Project root: `/Users/linusnadig/Developer/privat/games/yandere_demo/`. The git repo root is `/Users/linusnadig/Developer/privat/games/`.
- Commits start with `wip:`, `feat:`, `fix:` or `refactor:`. Never push. Never use `--no-verify`. Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**GDScript style**
- Explicit static types on every variable, parameter and return.
- Typed signals.
- `@onready var x: Type = $Path` for node references.
- PascalCase for nodes and scenes, snake_case for files, functions, variables and signals.
- No abbreviations and no single-letter names, including loop variables.
- Physics in `_physics_process`, logic in `_process`.
- Every character is a `CharacterBody3D` using `move_and_slide()`.
- Minimal comments: only the non-obvious why.

**Asset export**
- GLTF 2.0 `.glb`, 1 Blender unit = 1 m, −Z forward, Y up (`export_yup=True`).
- Principled BSDF materials, named `M_<Part>` (for example `M_Skin`, `M_Hair`, `M_HairStreak`, `M_Eye`, `M_UniformWhite`, `M_UniformRed`, `M_Neckerchief`, `M_Sock`, `M_Shoe`, `M_Bow`).
- Read enum identifiers from `bl_rna` instead of hardcoding them.
- Look shader nodes up by `type`, never by name.
- **Required object names:**
  - `TargetChar` is the target's armature, and the root of `target.glb`.
  - `Target-col` is the target collision proxy.
  - `Player-col` is the player collision proxy. It is exported as `Player-convcol` so Godot builds a convex shape.
  - `Locker-col` is the locker collision.
  - `School-navmesh` is not used: navigation is baked in Godot, which the spec §7 leaves to the builder.
- **Collision proxies on characters:** the `character_post_import.gd` script (Task 7) replaces the generated static body with a convex `Shape3D`. It stores the shape as root metadata `body_shape`, because a `CharacterBody3D` can't use a trimesh `-col`.

**Tooling**
- Before editing any `.tscn` by hand, verify the node paths with godot-mcp (`get_project_info`, `run_project` + `get_debug_output`).
- Prefer building complex scene structure in `_ready()` from Blender markers rather than hand-editing `.tscn`.

**Content**
- Use the modest uniform from the spec §4.1: full-length top and knee-length skirt.
- No violence or rival mechanics.
- Every tuning number lives in `data/`. The values in this plan are the defaults.

**Test commands** (all run from the repo root):
- import: `godot --headless --path yandere_demo --import`
- unit: `godot --headless --path yandere_demo --script res://tests/run_tests.gd`
- integration: `godot --headless --path yandere_demo res://tests/integration/<name>.tscn`
- all: `bash yandere_demo/tests/run_all.sh`
- Blender build: `/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python yandere_demo/blender/<script>.py`

## Review Focus

1. **Fast-forward or a large time step crossing more than one block boundary.** Each skipped block must still emit `block_changed` in order, and attendance must still record a skip. The test is in Task 2: `test_large_delta_emits_every_block_in_order`.
2. **The player hides while the target is in Notice or Suspicious, just below 100.** Suspicion drains, she must not report afterwards, and she resumes her plan. The test is in Task 4 (`test_hidden_drain_never_reports`) and Task 16 (`target_hide_resume.tscn`).
3. **She can't reach an activity anchor** (path blocked by players or students, or no path). She must not freeze. After 8 s with no progress she skips to her next planned activity. The test is in Task 15: `target_unreachable_anchor.tscn`.
4. **Exclusive player modes.** Sitting, hiding, camera mode and carrying an item interact. You can't sit or hide while in camera mode: entering either one exits camera mode first. Hiding is blocked below 10 Sanity. A carried item survives sitting. The test is in Task 13: `test_mode_exclusivity`.
5. **A missing, corrupt or older-version save file.** Continue is disabled, New Week works, and nothing crashes. The test is in Task 6: `test_load_corrupt_returns_null`.

**Planning rules** (pinned by the tests):
- **CLASS blocks** return a single `attend_class` activity.
- **cleaning** returns `cleaning_duty`. **going_home** returns `go_home`.
- **before_school** always starts with the fixed `arrive_locker` activity.
- **Free blocks** draw activities until the summed `duration_minutes` is ≥ 0.85 × the block length. The last activity is trimmed so the sum is ≤ the block length, which leaves travel slack.
- **Weight:**
  - start from `base_weight`
  - × 0.25 if the activity is already in `history.today_ids`
  - × 0.4 if it's in `history.yesterday_by_block[block_id]`
  - × 0 if it's the same as `previous_id`
  - × 0 if `block_id` isn't in `allowed_blocks`
- **Random draws:**
  - duration from `[min_minutes, max_minutes]`
  - anchor index from `[0, anchor_counts[id] - 1]`
  - 0–2 micro-stops
  - walk speed scale from `[0.9, 1.1]`
- All randomness comes from one `RandomNumberGenerator` seeded with `rng_seed`.

**Spec addendum:** `docs/superpowers/specs/2026-10-26-astolfo-target-design.md`. Read it fully before any Phase D task. It supersedes spec §4.1 and §4.1b wherever they conflict, outfit included: the model's outfit is kept exactly as is.

Phase D replaces the procedural target with the user-supplied Astolfo Source model. The game must work at parity after every task: all of `run_all.sh` passes and `validate_assets.py` exits 0.

Phase D notes (they bind every Phase D task):
- **SourceIO** (REDxEYE/SourceIO 5.5.4, MIT) is only needed by the one-time import in Task 23a.
  - Load it from an isolated `BLENDER_USER_SCRIPTS` directory under the session scratchpad.
  - Never install it into the user's Blender.
  - Import with `import_animations=False`; the animation import crashes on this model.
  - A normal rebuild works from the committed `astolfo_source.blend`.
- **Contract names stay**, so Tasks 15–20 keep working:
  - the root `TargetChar`, `Target-col`, the humanoid bone names (`HUMANOID_BONES`)
  - the project's chain naming scheme (`braid_NN`, `braid_bow`, `hair_front_*`, `hair_side_*`, `ahoge_NN`, `skirt_CC_SS`)
  - every clip name with its loop mode and length (addendum §3.5)
  - every expression name (addendum §3.4)
- Structural tests are rewritten to match the model, as described under addendum §6, "Tests describe behaviour".
- **The anti-goals** in addendum §5 bind every clip, pose, physics value and camera.

**Review Focus (Phase D):**
- The skirt at its maximum physics lift, seen from every camera position the player can reach (third-person rig and viewfinder, at standing and crouch heights). Expected: nothing under the skirt is ever visible.
- Task 15's AI with the new clips. Expected: `target_routine` and every T15–T20 integration test still pass, with no foot sliding at walk speed 1.3 m/s.
- R9 props on the renamed hand bones. Expected: the book, phone, can and broom sit in the hand and don't float.
- ExpressionController on meshes that lack a shape key. Expected: silently skipped, no engine error.
- A rebuild on a machine without SourceIO. Expected: `build_target.py` works from the committed `.blend`.

### Task 23a: Astolfo source import, rig conversion and the parity export

  - `blender/source/README.md`: how to re-import, including the SourceIO setup.

- Modify:

**Interfaces:**

- **Produces: `target.glb`**

    - The model's hair, bow and ribbon chains are renamed into the project scheme, counted as the model has them:
      - `braid_NN` and `braid_bow` (`braid_bow_NN` if it is a chain)
      - `hair_front_{L,C,R}_NN`, `hair_side_{L,R}_NN`
      - `ahoge_NN` if present

  - **Height:** crown at 1.62 ± 0.005 m, uniform scale. Limb fixes within ±5% are allowed (addendum §6).
  - **Meshes:**
    - The model's split, renamed `Target<Part>`: `TargetBody`, `TargetFace` (head), `TargetHair`, `TargetTop` (shirt), `TargetSkirt`, `TargetSocks`, `TargetShoes`.
    - `Target-col` is a capsule proxy (`M_CollisionProxy`, identity transform, Ruling R4) fitted to the new body.
  - **Materials:** Principled BSDF named `M_<Part>`, with the model's textures and outfit unchanged.
  - **Shape keys on `TargetFace`:**
    - `neutral`, `startled`, `suspicious`, `happy`, `blink`, `smile`, `sad`, `blush`, `wink_L`, `wink_R`, `mouth_A`, `mouth_I`, `mouth_U`, `mouth_E`, `mouth_O`, `pupil_small`, `pupil_large`
    - Each is baked as a composite of the model's flexes, recorded in a mapping table in `lib/astolfo.py`.
    - `blush` may be a placeholder composite until Task 23d.
  - **Clips:** all 18 from addendum §3.5, same names, frame counts and loop modes, regenerated on this rig.

**Interfaces:**
- **Consumes:** the Task 23a chains, the Task 23b clips, Task 13's `PlayerCameraRig` (its spring-arm length and offsets, and the viewfinder height), and `PhysicsLayers`.
- **Produces:**
  - Per-chain spring values for the hair clusters, ahoge, braid, braid bow, head bows, ribbons and skirt, each with explicit colliders (thigh, hip and chest capsules fitted to this body).
  - No spring on the `*_helper` bones.
  - **No hard lift limit up front (user).** The coverage test decides whether one is needed (see Step 3).
  - The skirt is lively in walk, look_around, startled and the idles: hem lift is ≥ 0.03 m at peak.

- [ ] **Step 1: Write the failing tests.**
  - **R10 probe:** with the springs active, max braid and bow drift from the baked pose is < 0.08 m in `target_idle_playful` and `target_walk_routine`, and the bow stays outside the skirt.
  - **`target_skirt_coverage.gd`:**
    - It plays `target_walk_routine`, `target_look_around`, `target_startled`, the three idles and the three seated clips, with the springs active.
