# Yandere Demo

A third-person stealth and photo game, made in Godot 4.7 with scripted Blender assets. You secretly follow one target
student through a five-day school week. Watch him, photograph him, collect what he leaves behind, and don't let him or
the school notice you. The week ends in one of four endings, decided by your photos and the intel you've gathered.

The demo has no violence and no rivals. There's one target, and he uses he/him in all game text.

## Requirements

- Godot 4.7.2 (`godot` on the PATH, for example `/opt/homebrew/bin/godot`)
- Blender 5.2, only needed to rebuild the 3D assets
- Python 3, only needed to re-synthesize the audio

Every command below runs from the repository root, the folder that contains `yandere_demo/`.

## Run

```sh
godot --path yandere_demo
```

The game opens on the main menu. **New Week** starts Monday. **Continue** resumes the saved week; progress is saved to
`user://save.json` after each completed day. You can also open `yandere_demo/project.godot` in the Godot editor and press
Play.

## Controls (keyboard and mouse)

| Key | Action |
|---|---|
| WASD | move |
| Shift | run |
| C | crouch toggle |
| E | interact (sit, hide, pick up, stash) |
| RMB | camera mode |
| LMB | snap |
| F | flash toggle |
| Q (hold) | Yandere Vision |
| T (hold) | fast-forward time |
| Tab | album |
| Esc | pause |

The mouse looks around. In camera mode, the mouse wheel zooms.

## Play in brief

- The day runs from 07:00 to 18:00. When the class bell rings, you have about 30 s to sit at your desk in 1-A (press E
  at the seat). Being late or skipping class raises School Alert.
- **Suspicion** rises while he sees you and drains while you're hidden. It is his meter. At 100 he reports you.
- **School Alert** rises when the teacher catches you out of class, running in the halls, using the camera on students
  or carrying a stolen item. At 100 you're sent to the principal.
- **Sanity** drains while he's out of sight and recovers while you watch him. Low Sanity has side effects, but it never
  ends the day by itself.
- Hide in hallway lockers or under desks. Stash the items you pick up at your shoe locker to keep them.

## Tests

```sh
bash yandere_demo/tests/run_all.sh
```

This reimports the project, runs the unit tests (`tests/run_tests.gd`) and then every integration scene in
`tests/integration/`. All of it runs headless. An integration scene also fails on any engine error.

Single runs:

```sh
godot --headless --path yandere_demo --import
godot --headless --path yandere_demo --script res://tests/run_tests.gd
godot --headless --path yandere_demo res://tests/integration/<name>.tscn
```

Godot doesn't reimport a `.glb` when only its post-import script has changed. After changing
`assets/models/*_post_import.gd` or `scripts/core/toon_converter.gd`, delete `yandere_demo/.godot/imported/` and import
again.

### Visual captures

These scenes need a window, so `run_all.sh` doesn't run them. They save PNGs to `user://captures/`, which on macOS is
`~/Library/Application Support/Godot/app_userdata/Yandere Demo/captures/`.

```sh
# The target: front, 3/4, side and back; every expression; the walk at four phases; the hand-prop clips
godot --path yandere_demo res://tests/visual/capture_target.tscn

# One test-mode day: hallway, courtyard, cherry trees, hide spots, viewfinder, Yandere Vision, camera prop,
# every UI screen, the main menu, and the stranger and cherry-tree endings
godot --path yandere_demo res://tests/visual/capture_gameplay.tscn

# A 6 s, 30 fps PNG sequence: walk -> target_sit_down -> target_sit_read at the courtyard bench
godot --path yandere_demo --write-movie /tmp/movie/frame.png --fixed-fps 30 \
    res://tests/visual/capture_gameplay.tscn -- --movie [--movie-activity=desk_phone]
```

The capture window stays on top and doesn't take keyboard focus. macOS stops drawing a window it can't show, for
example when the display is asleep, and the captures then stall or repeat one frame. Keep the screen awake while they
run.

## Rebuild the assets

Every mesh, rig, animation and texture is generated by the scripts in `yandere_demo/blender/`, except the target's
model: `build_target.py` converts a user-supplied Source Engine model from `blender/source/astolfo/` (private use
only, see `blender/source/README.md`) and keys his clips on it. The `.blend` files and the exported `.glb` files are
committed, so you only need these commands after changing a build script.

```sh
BLENDER=/Applications/Blender.app/Contents/MacOS/Blender
$BLENDER --background --factory-startup --python yandere_demo/blender/build_all.py      # target, player, students, teacher
$BLENDER --background --factory-startup --python yandere_demo/blender/build_school.py   # school environment
$BLENDER --background --factory-startup --python yandere_demo/blender/validate_assets.py  # must exit 0
```

`build_target.py`, `build_player.py`, `build_students.py` and `build_teacher.py` also run on their own. Each one
exports GLTF 2.0 into `yandere_demo/assets/models/`: 1 unit is 1 m, −Z forward, Y up. Reimport in Godot afterwards
(see Tests).

The audio is synthesized offline:

```sh
python3 yandere_demo/tools/synth_audio.py yandere_demo/assets/audio
```

## Layout

| Path | Contents |
|---|---|
| `scenes/` | `main.tscn` (one school day), `ending.tscn`, the characters, `props/`, `ui/` |
| `scripts/` | gameplay nodes and autoloads (`game_manager.gd`, `school_clock.gd`, `sanity_system.gd`, `audio/audio_director.gd`) |
| `scripts/core/` | pure logic: scheduler, meters, scoring, save, tuning resources |
| `data/` | every tuning number: schedule, activity pool, items, intel cards, stealth, cast, endings |
| `assets/` | the generated models, textures, toon shaders and synthesized audio |
| `blender/` | the asset build scripts and their `.blend` output |
| `tests/` | unit, integration and visual tests |

## Known limitations

- The demo runs from the editor or the CLI only. There is no export preset, no gamepad support and no mid-day save.
- The UI doesn't scale with the window. It is laid out for 1152×648 and stays readable up to 1920×1080.
- The target's seat entry is a short straight side-glide (ruling R12): his feet stay planted for about 0.3–0.5 m as he
  lines up with a bench or desk. A side-step clip would fix this.
- Hiding under a desk reuses the standing crouch clip. The pose pokes through the tabletop, but the player never sees
  it: the peek view doesn't render the player's own body.
- The stranger ending ignores the `EndingCamera_stranger` marker. EndingDirector places that camera at runtime
  (ruling R31).
- The door of a hide locker is a plain panel 3 cm in front of the baked locker face, without the baked vents.
- The sounds are synthesized and haven't been tuned by ear.
